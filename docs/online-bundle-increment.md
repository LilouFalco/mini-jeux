Real deployment options

A. SQL for the non-chess games plus a separately installed authenticated server validator
for chess, such as a Supabase Edge Function. This requires TWO deployment surfaces: SQL
Editor plus function deployment. SQL alone cannot install that JavaScript function.
No administrative/function deployment credentials or capability are assumed. The service
must verify the caller JWT, load canonical state/member seat from DB, validate move history,
and commit through a service-only RPC with row lock, membership/game/version/instance
rechecked atomically and deduplicated action key. No client execute grant on that commit RPC.
Service credentials stay only in server environment. A racing validation must fail stale,
not overwrite newer state. This integration is NOT built yet.

B. Keep chess offline until that service can be installed; finish one SQL bundle for the
other games. This avoids claiming that a generic state-update RPC validates chess.
